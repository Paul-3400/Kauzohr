---

## 🔀 Lösungsweg: Drei Ansätze

### ❌ Ansatz 1: ALSA Loopback (gescheitert)

- `snd-aloop` geladen, Loopback funktionierte nativ
- Docker-Container blockiert Zugriff auf `/proc/asound`
- `--device /dev/snd` reichte nicht aus
- **Fazit:** ALSA Loopback + Docker = Sackgasse

### ❌ Ansatz 2: PulseAudio Bridge (verworfen)

- Zu komplex, fragil, Overkill für den Use-Case

### ✅ Ansatz 3: RTSP-Stream (Erfolg!)

- **mediaMTX** als RTSP-Server
- **ffmpeg** als persistenter Encoder (PCM → Opus → RTSP)
- **receiver.py v1.4** streamt WAV-Daten + Stille via pipe → ffmpeg
- **BirdNET-Go** liest RTSP-Stream nativ

## 📡 Architektur (final)

```
ESP32 (XIAO-S3)
  │ HTTP POST /upload
  │ Header: X-Battery-Voltage: 3.905
  │ Body: WAV (48kHz, 16bit, mono, 20 sek)
  ▼
receiver.py v1.4 (Flask, Port 5000)
  │ 1. Batterie-Header lesen
  │ 2. Kalibrierung: V_echt = V_roh × 1.0548 + 0.0
  │ 3. voltage_log.json schreiben (kalibriert)
  │ 4. WAV speichern
  │ 5. PCM-Daten → ffmpeg stdin (pipe:0)
  │ 6. Zwischen WAVs: Stille-Generator (0.5s Chunks)
  ▼
ffmpeg (persistent, PID-überwacht)
  │ -f s16le -ar 48000 -ac 1 -i pipe:0
  │ -acodec libopus
  │ -f rtsp rtsp://127.0.0.1:8554/birds
  ▼
mediaMTX (RTSP-Server, Port 8554, API 9997)
  │ Pfad: /birds
  ▼
BirdNET-Go (Docker, Port 8080)
  │ rtsp://10.0.1.196:8554/birds
  │ ONNX-Modell: 6522 Arten, 180 nach Range-Filter (CH)
  ▼
🐦 Vogelerkennungen im Dashboard!
```

## 🔋 Batterie-Kalibrierung

### Problem

ESP32 ADC misst systematisch zu tief (Spannungsteiler-Toleranz, ADC-Nichtlinearität).

### Lösung: Ein-Punkt-Kalibrierung im receiver.py

| Parameter | Wert |
|---|---|
| **Eichpunkt** | Voltmeter: 4.079V, ESP32 roh: 3.867V |
| **Faktor** | 1.0548 |
| **Offset** | 0.0 (für späteren 2. Messpunkt) |
| **Formel** | `V_echt = V_roh × 1.0548 + 0.0` |

### Dreifach-Validierung ✅

| Quelle | Wert | Status |
|---|---|---|
| Voltmeter (Eichpunkt) | 4.079 V | ✅ |
| Dashboard (kalibriert) | 4.121 V | ✅ |
| TP4056 Laderegler-Kennwert | ~4.12 V | ✅ |

**Genauigkeit: ~0.6%** – hervorragend für ESP32 ADC!

### Code-Stellen in receiver.py

```python
# Config-Sektion (oben):
BATTERY_CAL_FACTOR = 1.0548
BATTERY_CAL_OFFSET = 0.0

# Upload-Funktion:
battery_raw = request.headers.get("X-Battery-Voltage", "n/a")
if battery_raw != "n/a":
    v_raw = float(battery_raw)
    battery_v = round(v_raw * BATTERY_CAL_FACTOR + BATTERY_CAL_OFFSET, 3)
```

### Spätere Zwei-Punkt-Eichung

Bei Verfügbarkeit eines leeren Akkus (~3.3V) zweiten Messpunkt nehmen:

```
a = (V_echt2 - V_echt1) / (V_roh2 - V_roh1)
b = V_echt1 - a × V_roh1
```

### Lesson Learned

> ⚠️ **nano-Editierung von Python-Code ist fehleranfällig!**
> Besser: Python-Scripts für gezielte Zeilenersetzung verwenden, oder ganzen Block als .md-Container liefern.

## 🧠 Erkenntnisse fürs Notizbuch

1. **Docker + ALSA = schwierig** – `/proc/asound` im Container nicht verfügbar, `--device /dev/snd` reicht nicht
2. **RTSP ist die elegantere Lösung** – netzwerkbasiert, kein Kernel-Modul, Docker-freundlich
3. **mediaMTX** ist leichtgewichtig und zuverlässig als RTSP-Server
4. **ffmpeg persistent** via subprocess.Popen + pipe:0 funktioniert stabil
5. **ESP32 ADC-Kalibrierung** mit Faktor 1.0548 erreicht ~0.6% Genauigkeit
6. **Dreifach-Validierung** (Voltmeter → Formel → Laderegler-Kennwert) gibt hohe Sicherheit
7. **nano-Editierung** von Python ist fehleranfällig → lieber sed oder Python-Script verwenden
